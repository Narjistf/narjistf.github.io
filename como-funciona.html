Cómo llega narjis.es a tu pantalla

Escribes nueve letras y en menos de un segundo ves una página que está guardada en un ordenador de GitHub, al otro lado del mundo. Por el camino intervienen cinco sistemas distintos.

El viaje, paso a paso

  1. Escribes narjis.es

    Tu navegador no sabe dónde está «narjis.es». Internet no funciona con nombres sino con números: las direcciones IP, como 185.199.108.153. Necesita traducir el nombre a un número.

  2. Pregunta a la guía telefónica de internet

    Esa traducción la hace el DNS (sistema de nombres de dominio). Tu navegador pregunta a un resolvedor DNS, normalmente el de tu compañía de internet. Si alguien ha preguntado por narjis.es hace poco, ya tiene la respuesta guardada y salta al paso 6.

  3. Los servidores raíz

    Si no la sabe, el resolvedor empieza por arriba: los servidores raíz. No conocen narjis.es, pero saben quién lleva todos los dominios que terminan en .es.

  4. El registro de .es

    Los dominios .es los gestiona Red.es. Cuando se compró narjis.es, se le dijo al registro que sus nameservers (los servidores que guardan la información del dominio) son los de Cloudflare. Así que responde: «pregunta a Cloudflare».

  5. Cloudflare da la dirección

    En Cloudflare hay unos registros DNS, como fichas de una agenda. Los registros de tipo A dicen «narjis.es está en 185.199.108.153» (y en otras tres direcciones de reserva). Esas direcciones son de GitHub.

  6. Conexión segura con GitHub

    Con la dirección, tu navegador llama a GitHub Pages por HTTPS. Primero comprueban un certificado que demuestra que ese servidor puede hablar en nombre de narjis.es; es el candado de la barra de direcciones. Todo lo que viaja después va cifrado.

  7. GitHub busca la web correcta

    Los mismos servidores de GitHub alojan millones de webs. El navegador dice «quiero narjis.es» y GitHub busca qué repositorio tiene un archivo CNAME con ese nombre: narjistf.github.io. De ahí envía index.html.

  8. Tu navegador dibuja la página

    El archivo llega como texto. El navegador lee las etiquetas HTML (<h1> es un título, <p> un párrafo), aplica el estilo CSS (colores y letras), descarga las fuentes y la pinta en la pantalla.

Y cuando cambio algo, ¿cómo llega?

Cuando editas un archivo en GitHub y pulsas Commit changes, Git guarda una foto nueva de todos tus archivos con un mensaje que explica el cambio. Esa foto se llama commit y queda en el historial para siempre: puedes volver a cualquier versión anterior.

Cada commit en la rama main despierta a GitHub Actions, un robot que copia tus archivos a los servidores de GitHub Pages. Tarda uno o dos minutos; lo puedes ver en la pestaña Actions de tu repositorio. Mientras tanto, la gente sigue viendo la versión anterior.

Pruébalo tú

Puedes hacer tú misma la pregunta del paso 2. En Windows abre «Símbolo del sistema»; en Mac, «Terminal». Escribe:

nslookup narjis.es

La respuesta debería mostrar las direcciones 185.199.108.153 a 185.199.111.153. Si sale otra cosa, los registros de Cloudflare no están bien. Para preguntar directamente a Cloudflare, como en el paso 5:

nslookup -type=NS narjis.es

Esto muestra los nameservers del dominio, que deben terminar en ns.cloudflare.com.
